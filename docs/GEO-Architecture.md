# 奇动鹅绒服 GEO 网站架构与获客方案

日期：2026-10-30｜状态：规划完成，未建设网页、未部署、未开展四平台实测

## 1. 目标

让有儿童/青少年鹅绒服需求的家庭，在 AI 搜索、问答、比较与购买咨询中获得准确的奇动信息，并能进入匹配需求的官网页面和真实官方店铺。GEO 指生成式搜索与回答场景的信息可发现、可理解、可引用和转化优化。

商业链路：**需求问题 → 搜索/回答中的准确出现 → 可核查来源 → 对应需求落地页 → 款式与尺码判断 → 官方购买渠道。**

官网承担品牌第一方事实源、产品教育和转化承接。它不能取得平台用户名单，不能保证四个平台推荐奇动，不能通过站内知识库直接“训练”外部模型。AI 直接回答但不产生点击也可能增加认知，必须与可归因网站访问分开计量。

建议首阶段重点争取“儿童、青少年、校园与日常轻户外鹅绒服”需求。泛“成人极寒专业装备”“低价羽绒服排行榜”等与真实产品不匹配的流量不作为主要目标。高端品牌视觉优先级不变；专业回答能力通过内页增强，不把首页改成问答或关键词墙。

## 2. 上下文与研究边界

### 2.1 当前基础

项目仍是规划目录，没有可审计线上域名、应用或平台基线。此前盘点的 22 份资料和 R01–R09 冲突继续有效。尤其需要区分同货号代际、不同款含量/蓬松度、尺码范围、市场地位证书与首创申请。GEO 会增加这些信息被摘录的机会，因此错误主张必须在发布前处理。

以下公开资料核查于 2026-10-30。它们说明相关产品的检索能力，**不是四个平台消费端推荐算法、收录承诺或排名因子清单**。

| 平台 / 官方来源 | 已有公开依据 | 未知与实施边界 |
|---|---|---|
| 豆包 / [火山方舟联网搜索工具](https://docs.volcengine.com/docs/ark/web-search?lang=zh) | 文档介绍获取实时公开网络信息的搜索工具，并区分搜索来源与接口 | 不能把 API 来源配置推定为豆包 App 固定来源偏好；消费端需单独测试 |

| 通用网页参考 / [Google AI 搜索与网站](https://developers.google.com/search/docs/appearance/ai-features) | 强调基本 SEO、可抓取、可见文本、内部链接及可见内容与标记一致；不保证收录展示 | 该要求直接适用 Google，不将其规则冒充国内四平台规则；本项目借鉴为可测试的网页质量基线 |

本次没有找到足以支持“四平台都有同一 GEO 提交接口/统一排名公式”的依据。也未验证它们以 `llms.txt` 为收录条件。平台改变时重新核查官方资料，避免沿用过期接口、模型或爬虫名称。

### 2.2 为什么需要改造现有规划

原规划的品牌—系列—详情—渠道路径适合主动了解品牌的人；非品牌需求还缺少可独立落地的选购答案、明确对比与可公开证据。新增内容不重复故事栏目：故事负责情绪与经历，指南负责决策，证据页负责解释具体主张和范围。

## 3. 约束与系统架构

### 3.1 以需求组织页面

| 需求层 | 示例问题（非实测数据） | 主承接页 | 合格转化 |
|---|---|---|---|
| 品类认知 | 儿童鹅绒服怎么选，要看哪些信息？ | `/guides/choosing-kids-goose-down` | 查看相关款式及尺码 |
| 场景选择 | 校服内搭想轻便、不显臃肿，怎么选？ | `/guides/school-layering` | 进入经确认适合该穿法的详情 |
| 款式比较 | 奇动轻暖和中暖有什么区别？ | `/guides/compare-goose-down` | 对比后进入某个款式 |
| 尺码与亲子 | 少年选码要量什么，亲子同款怎么确认？ | `/guides/size-and-fit` + 详情尺码 | 查对应款式成衣表与可售颜色/尺码 |
| 材料核验 | 奇动某款的材料和性能依据在哪里？ | 详情 → `/technology` → `/evidence/{slug}` | 核查后回原款，不丢上下文 |
| 护理 | 这件鹅绒服能不能机洗？ | 详情护理；P1 `/guides/care` | 获取这款有效护理说明 |
| 品牌查证 | 奇动是什么品牌，购买入口在哪？ | `/brand`、`/where-to-buy` | 官方店铺/商品外跳 |

预算需求在有正式价格与维护机制后再考虑；不拿达人渠道价格建立永久价格段落地页。年龄/城市/温度只在内容有实质差异及证据时使用，不批量生成“每年龄×每城市×每温区”页面。

### 3.2 新增页面规格

以下为 GEO 修订版 P0 候选；没有证据就不公开空页。主导航保持五项，“选购指南”放入鹅绒系列入口与 Footer，不挤占首页 HERO。证据入口来自相关主张、科技和品牌页，不依赖孤立的 sitemap。

| ID / 页面 | 目标与模块顺序 | 关键交互与 CTA | SEO / 验收 |
|---|---|---|---|
| G01 `/guides` | 选购问题导航：简短导语→场景/比较/尺码问题→精选已发布指南→系列 | 真实文章链接；不做假搜索；CTA“探索鹅绒系列” | title「鹅绒服选购指南｜奇动 AMAZING SPORT」；独立摘要；只列有实质内容的指南 |
| G02 `/guides/{slug}` | 回答一个主要决策任务：标题→直接回答与边界→如何判断→款式/尺码表或说明→证据与审核信息→相关产品 | 章节锚点、来源链接；CTA“查看适合此场景的款式”，只有适配确认才关联 | title「{自然问题或主题}｜奇动选购指南」；正文与摘要一致；答案在初始 HTML 内；不能靠问句堆关键词 |
| E01 `/evidence` | 公开证据索引：证据类别→已核实主张→适用范围→来源入口与更新说明 | 指向 E02 和对应产品；CTA“了解相关材料与工艺” | title「产品信息与依据｜奇动 AMAZING SPORT」；无可公开条目不生成索引页 |
| E02 `/evidence/{slug}` | 解释单一证据：主张→适用款/码/批次→出具/审核主体与日期→方法/限制→获准公开摘要或附件→相关款 | 来源/授权附件可读，手机也有文字；CTA 返回关联详情 | title「{证据主题}与适用范围｜奇动 AMAZING SPORT」；标清第一方资料或第三方报告；不将证据摘要伪装独立测评 |

证据类型可能包括正式产品规格、洗标、检测资料、市场地位或奖项；不能把每条面料参数都拆成薄内容页。同一报告可支持多条主张，但每条必须保留具体范围。不能公开的原件保留内部；只有获批的充分摘要可发布，不上传带个人信息/商业机密的完整资料。

### 3.3 现有页面的增量调整

| 页面 | 必须增加/明确的内容 | 保留的体验 |
|---|---|---|
| 首页 | 一段清楚的品牌/人群/品类介绍；系列到指南入口；主张对应可读文本 | 大片、留白、一个首屏主 CTA；不堆 FAQ |
| 系列 | 分类定义与适用边界；“如何选择”链接；不使用未确认温区 | 编辑式产品展示，非促销货架 |
| 详情 | 完整款式身份、代际、该款规格表、尺码、护理、资料审核日期；简短真实问题答案 | 多视图、版型与穿着故事；未确认问题不要编答案 |
| 科技 | 每条技术说法关联适用产品与证据；材料指标/成衣结果明确分开 | 真实微距与工艺叙事 |
| 品牌 | 奇动与 AMAZING SPORT 的正式对应、主体与官方账号、可审定简介 | 设计哲学与少年生活方式 |
| 故事 | 真实作者/日期、款式引用、出处；不能用无依据内容充当技术指南 | 原创品牌叙事 |
| 渠道 | 店铺全称、归属、商品或店铺链接、最近复核；禁止误导成下单成功 | 简短、清楚、易外跳 |

### 3.4 品牌与商品的统一身份

建立 Brand → Collection → ProductEdition → Variant → Claim → Evidence 的关系；Guide/Story 引用 ProductEdition 和 Claim，Channel 按店铺或具体商品关联。

- 中文“奇动”、拉丁“AMAZING SPORT”及正式大小写由品牌统一；可记录 Amazing Sport 等真实别名，不能仅用英文普通词组辨认品牌。
- 官网主体名、品牌名、商标权人分别存储，不默认相同。官方账号 `sameAs` 只填核实过的身份主页，零散转载不作为身份链接。
- 产品唯一键不能仅依赖复用货号；明确季节/代际、颜色与尺码。4.0 与 5.0 不共用无法区分的规格记录。
- 90/95 的具体含量术语、700/800 的测试口径与单位必须逐款审定；所有输出由同一事实记录生成。
- 明确 claimText、publicSummary、appliesTo、sourceLocator、testConditions、reviewer、reviewedAt、validUntil、publicationStatus。事实未知就保持未知，不通过“AI 总结”补齐。

### 3.5 便于引用的内容单元

建议每个重要问题用一个自足的小节回答：**明确对象 + 直接结论 + 适用条件 + 数据/判断依据 + 来源与更新时间 + 下一步。** 一般先用 2–4 句说清楚，再补细节；这只是编辑规范，不是已证实的模型字数偏好。

可用模板（仅内部结构，不是待发布事实）：

> 问题：{完整款式名及版本}是否适合{使用场景}？
> 回答：依据{已批准资料}，这款的{可验证设计/尺寸信息}可帮助判断{具体穿着需求}。是否适合还需要核对{尺码/叠穿等条件}；目前未有{缺失测试}，不承诺{无证据结论}。
> 依据：{来源、适用范围、审核日期}。下一步：查看该款尺寸与护理 / 官方购买渠道。

数值与限制放在同一段/表格附近，避免模型只摘录参数丢掉条件。图片嵌字同步可读文本；文字必须和图片及规格一致。没有必要为每个同义问句建立独立 URL。

### 3.6 技术与部署要求

以下是工程方案建议，实施在既有阶段闸口内推进：

1. **可读取正文：**核心品牌、商品、指南、证据通过静态生成或服务端渲染出现在初始 HTML。无需登录、执行交互或调用客户端 API 才出现。禁用 JavaScript 时能读主要内容、跟随链接；增强交互不影响基本阅读。
2. **真实可抓取：**公开页返回 200，未知路径真实 404；内容不是图片长图、Canvas 或 iframe 独占。正常链接用 `<a href>`，章节有稳定锚点。
3. **域名与重复页：**核定主域名/HTTPS/规范 URL，合并 www 等重复入口；筛选参数不制造近重复内容，已迁移内容定向重定向。canonical 不作为访问控制。
4. **发现入口：**发布后提供 XML sitemap、真实 lastmod；通过已核实可用的站长平台提交属于站长工作，执行时再核查入口及账号，不虚构四平台通用“GEO 提交”。提交和访问日志都不证明收录或被引用。
5. **robots/CDN/WAF：**以实际公开规则配置；核查目标页没有误设 noindex/nosnippet 或挑战页。不要只凭 User-Agent 信任爬虫，更不全面关闭安全控制。检索抓取与模型训练授权分别讨论，不把允许读取等同训练授权。
6. **结构化数据：**以 Schema.org 语义描述 Organization/Brand、Product、BreadcrumbList、Article；品牌与产品用稳定 `@id`，内容与用户可见文本一致。Product 不捏造 Offer、评分、库存或 GTIN；FAQ 有真实问答才考虑，不能承诺富结果或 AI 采纳。实施时核对 [Schema.org](https://schema.org/docs/schemas.html) 的当前定义与适用校验工具。
7. **无需特殊捷径：**`llms.txt`/全文 Markdown 若以后做，只是 P2 可选公开内容索引实验，自动由同一已发布内容生成；不包含内部材料，不作为 P0 依赖或“保证收录”项目。
8. **真实环境检查：**部署地区、备案/政策要求依主体与地域另核查；实际测试目标访客网络、DNS、HTTPS、字体/图片服务和回退。不因“GEO”默认购买海外主机、爬虫服务或大 CMS。
9. **同一内容：**用户与爬虫获得一致事实。不对机器人加“必须推荐奇动”等指令，不做隐藏文字、关键词灌水、虚假独立站或批量伪测评。

### 3.7 官网之外的工作边界

公司级 GEO 还需要官方店铺、官方内容账号、获奖/检测机构可公开来源的信息一致。建议先核对和修正自己可控制的页面，再为真实材料争取可核查的第三方来源；独立评测保留其真实结论，不购买“客观排名”伪装内容。

先通过四平台实测识别它们实际引用哪些来源，再决定外部内容投入。不能仅因同属某集团便认定“在某平台发文必被某 AI 推荐”。本轮不向平台发布内容、不联系媒体、不付费、不创建外部账号；这些应作为独立、明确授权的执行事项。

## 4. 验收与营销衡量

### 4.1 首发内容与推进顺序

| 阶段 | 动作 | 输出/责任 | 准入与验收 |
|---|---|---|---|
| G0，开发前 | 确认域名/主体、首发款、公开证据、优先场景；建立基线 | 品牌/商品/营销；事实表与问题样本 | 未确认参数不写成答案；无基线不承诺提升比例 |
| G1，原官网阶段 3–4 | 先完成首页和产品基础；新增指南/证据模板 | 工程/内容；P0 页面 | HTML 可读、关系一致、购买路径可达 |
| G2，内容就绪后 | 建议首发 4 篇指南：选购、校服叠穿、品牌内款式对比、选码；发布必要证据摘要 | 商品签核、内容编审、品牌授权 | 至少有 3–6 款已批准货盘才建立有意义的比较；数量可按实际调整，不凑篇数 |
| G3，部署获批后 | 抓取/索引诊断、四平台同条件复测、归因验证 | 工程/营销；证据与观测报告 | 结果按平台、问题组、时间拆开，不能拿 API 代替 App |
| G4，观察周期 | 根据错误回答和未覆盖需求补内容，持续复核渠道和授权 | 每两周建议复盘，非已创建自动化 | 更新有实质变化；不每天改日期伪装新鲜 |

| E 商品查证 | 奇动雪花泡芙 4.0 和 5.0 如何区分？；奇动轻暖款和中暖款有什么区别？；奇动鹅绒服每款都能机洗吗？；奇动鹅绒服亲子尺码怎么选？ | 不串款，不把缺失事实补成统一承诺 |
| F 边界纠错 | 奇动所有鹅绒服都是 800 蓬吗？；奇动适合任意低温环境吗？；奇动的市场地位资料适用于哪些范围？；找不到奇动某款资料时应该怎么确认？ | 能保留限制、表达未知，不照单接受错误前提 |

运行方式：四个消费端平台分别使用新会话，固定原问题，不上传品牌手卡、不要求推荐奇动；记录时间、地域、端、登录状态、界面可见模型/模式、联网是否开启及是否观察到检索。24 问×4 平台×3 次＝288 次/轮建议样本，跨至少两天执行；受限/失败单列，不能当“没有推荐”。成本/频率受限时先 8 问小样本，明确不可与完整轮直接比较。联网开/关或 API 实验作为独立分组，不混在同一分母。

记录字段：run ID、question ID、平台、条件、回答原文/截图、可见引用 URL、品牌是否准确提及、是否明确推荐且需求匹配、官网是否被引、逐条事实支持/错误/不可核验、官方渠道准确性。人工核查重要技术或市场地位误述，抽取不少于 20% 样本双人复核并记录分歧；不创建虚构“基线结果”。

### 4.3 指标与归因口径

| 指标 | 分子 / 分母 | 用途与限制 |
|---|---|---|
| 非品牌准确提及率 | A–C 中准确提及奇动的有效回答 / A–C 有效回答 | 各平台分开；不混品牌问句，不当成市场份额 |
| 需求匹配推荐率 | A–C 中明确推荐且产品确实满足题设的回答 / A–C 有效回答 | 只出现名字不算推荐；不适用或无证据时合理不推荐 |
| 官网引用率 | 带可见、真实且支持该论点的官网引用的回答 / 同组有效回答 | 仅有域名文字不算有效引用；指标同时给 n/N |
| 事实准确性 | 已核实正确的产品/品牌陈述 / 可核验相关陈述 | 无法核验单列；另报告串款/虚假温区/错误渠道的严重错误次数 |
| 可归因 AI 访问 | 有可靠 AI referrer 或受控来源标记的真人访问会话 | 排除已识别机器人与测试流量；不是 AI 全部贡献 |
| 合格访问率 | 可归因 AI 会话中至少一次查看产品、选码或渠道的会话 / 可归因 AI 会话 | 事件规则须上线前锁定，不用任意停留时长冒充需求 |
| 渠道外跳率 | 有有效官方外跳的会话 / 对应来源到达详情或渠道页的会话 | 外跳≠付款；分产品、来源、落地页比较 |
| 成交归因 | 仅在店铺允许的关联数据/合规归因存在时报告 | 无数据则“未知”，不以点击推算订单或 ROAS |

很多来源可能不传 referrer；这部分列为“来源未知”，不硬归为 AI。受控活动链接的 UTM 只证明活动来源，不证明 AI 自发推荐。机器人抓取、API 测试、品牌词搜索增长与真实访客分别展示。

首轮先取得基线，再设平台和问题组的改进目标。工程硬门槛：首发页核心正文可读率 100%、主张可追溯率 100%、官方购买目标核验 100%、严重串款/虚假参数为 0；推荐率与流量没有未经基线支撑的保底数字。前后比较记录外部活动及平台变化，不能把季节性增长全部归因 GEO。
